Buttons with a Brain

A "Send message" button that narrates its own lifecycle — idle, hover, loading, success, error — entirely through transform and opacity. Nothing snaps.

Demo

Duration & easing notes

Two buttons, one motion system — same tokens, different accent color, to prove it's a system rather than a one-off.

  • Hover / focus — 150ms, cubic-bezier(0.4,0,0.2,1). Fast enough to read as instantaneous feedback (under the ~200ms threshold where direct manipulation starts to feel laggy), so the button feels "alive" the moment you touch it.
  • Idle ↔ loading/success morph — 260ms, cubic-bezier(0.65,0,0.35,1). The pill "narrows to a circle" using transform: scaleX() on a separate layer, not width — so the shape change never triggers layout, only composition. 260ms is long enough to register as a deliberate shape change, short enough not to feel sluggish.
  • Content cross-fade — 180ms opacity + scale, ease-out. Label, spinner, checkmark, and "Retry" are stacked layers that fade in/out together rather than swapping — so there's never a frame with no feedback at all.
  • Success hold — 900ms before returning to idle. Long enough to actually read the checkmark before it disappears; shorter felt like a flicker in testing.
  • Error shake — 380ms, cubic-bezier(0.36,0.07,0.19,0.97) (a classic "impact and settle" curve) — one quick oscillation, not a cartoonish wobble, so it reads as "that didn't work" without being obnoxious.

Reduced motion: under prefers-reduced-motion: reduce (or the toggle above, for testing without changing OS settings), transitions collapse to near-instant, the shake is removed entirely, and the spinner switches from a rotating ring to a gentle opacity pulse. State is still always communicated — just without the motion.

Interruption handling: the button is disabled (pointer-events off) for the duration of loading and success, so spam-clicking can't start a second request mid-flight. Each send gets a generation counter — if a newer request starts, any stale timeout from an older one is ignored rather than fighting over the button's state.
